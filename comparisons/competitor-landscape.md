## 2. Deep dives

**`chuongmep/RevitAddInManager`** (502 stars, MIT, C#, last pushed 2026-08-30) solves a completely different problem than file parsing: it's a hot-reload add-in manager that lets Revit plugin developers modify and re-run their add-in code without closing and reopening Revit, plus bundled utilities (BIP Checker/Compare, startup manager, debug/trace console). It's a fork-and-extend of an original Autodesk sample, now maintained by ChuongHo with a WPF rewrite, supporting Revit 2019–2027. It ships only as a manual installer from GitHub Releases — no NuGet/npm/cargo package. There are no element-count or performance claims; its value is developer velocity, not data extraction. Actively maintained, with a healthy roster of named contributors and even JetBrains IDE sponsorship. It requires a running, licensed Revit instance by definition — it has nothing to say about headless or no-Revit workflows, and shares no technical surface with rvt-rs/ifc-lite.

**`datadrivenconstruction/cad2data-Revit-IFC-DWG`** (532 stars, pushed 2026-10-28 — the most recently active repo in this set) is the one genuine architectural peer to rvt-rs. Its README states plainly: "Revit 2016–2027 files are read directly, with no Revit installation needed" — the same clean-room, no-live-Revit value proposition rvt-rs offers. It ships as compiled desktop apps and CLI executables (`RVTconverter.exe`, `dwg2excel.exe`) for Windows x64, with Linux (x64/arm64) and macOS (arm64/x64) CLI builds in recent releases, batch-friendly exit codes, JSON status lines, Docker images, n8n workflows, and even "AI agent instructions" plus a dedicated MCP server wrapping the CLI. It exports to GLB/glTF/OBJ, IFC4 (with property sets, quantities, classification), and tabular JSONL/Excel/SQLite. The catch: licensing is split — workflows/docs/tools are MIT, but the actual converter binaries are proprietary, free only for non-commercial use, with commercial use (including any paid client work) requiring a license purchased from DataDrivenConstruction. It is not source-available for the core parsing engine.

**`ADN-DevTech/RevitTrainingMaterial`** (378 stars, MIT, last pushed 2021-05-03) is Autodesk's own official two-day Revit API training curriculum — labs in C# and VB.NET, slide decks, and sample .RVT files, dating back to 2013 and last touched in 2021. It is not a tool in any functional sense; it teaches developers to use the *official* Revit API (meaning: you must have Revit installed, referencing `RevitAPI.dll`/`RevitAPIUI.dll`, and you test by running Revit itself). Its presence in a competitor landscape is useful mainly as the baseline rvt-rs's clean-room reverse engineering approach is explicitly trying to avoid — rvt-rs lets you skip the licensed-Revit-plus-official-API dependency chain this material teaches people to build on. Zero stars-growth signal of recent activity; effectively an archived teaching resource.

**`McCulloughRT/Revit2glTF`** (200 stars, no declared license, last pushed 2024-04-08) is an unfinished, single-purpose glTF exporter add-in. Its own README is a to-do checklist with multiple unchecked boxes — textured material export, normals export, a toggle between per-element `.bin` files and a single `.glb`, and SQLite-referenced element properties are all still pending as of the last push. It has no CLI or headless mode; it runs as a Revit add-in and requires a live, licensed Revit session. The absence of any license file is a real adoption blocker for any company wanting to depend on it commercially. It has meaningful stars (200) relative to its unfinished state, suggesting name recognition in the "glTF from Revit" niche rather than production readiness.

**`cowboy1997/Revit2GLTF`** (197 stars, MIT, last pushed 2025-02-07) is a Chinese-market-oriented Revit-to-glTF exporter built around a C# wrapper for the Draco mesh-compression library, claiming very fast export speed and high compression ratios, plus a three.js-based online viewer demo. It supports Revit 2020–2023 — a narrower version range than most peers here — and ships only as a compiled MSI installer or via manual Visual Studio compilation against RevitAPI/RevitAPIUI. GitHub's language detection reports JavaScript as primary because of the bundled three.js viewer code, but the actual Revit-side exporter is C#. No IFC export, no MCP, no headless/CLI path — like the other glTF exporters, it is fundamentally a Revit add-in and therefore Revit-dependent.

**`bvn-architecture/RevitBatchProcessor`** (428 stars, GPL-3.0, last pushed 2026-10-13) is a mature, actively maintained batch-automation harness: point it at a list of .rvt/.rfa files and a Python or Dynamo script, and it drives real Revit sessions through each file automatically, handling dialogs, worksets, and central-file detachment. It explicitly requires "at least one version of Revit installed" — this is a stated hard requirement, not an oversight — and has a genuine headless CLI (`BatchRvt.exe --settings_file ...`), schedulable via Windows Task Scheduler. The original author (@DanRumery) has stepped back from active support per a banner at the top of the README, but the community (crediting contributors by name for Revit 2022–2027 upgrades) has kept it current, with Revit 2027 support shipped in the v1.13.1 beta referenced in the current README. It has no IFC export and no MCP integration — its entire model is "automate the real Revit application," the architectural opposite of rvt-rs's "never launch Revit at all."

## 3. Strategic verdict: where rvt-rs + ifc-lite actually fits

None of these six repos combine all three of: (a) reading Revit files **without Revit installed**, (b) a **permissive open-source license** usable commercially at zero licensing cost, and (c) **native AI-agent/MCP tooling** at scale.

- Five of the six (`RevitAddInManager`, `RevitTrainingMaterial`, `Revit2glTF` ×2, `RevitBatchProcessor`) require a live, licensed Revit installation by design — they are add-ins, training material, or automation harnesses that drive the real application. rvt-rs's entire premise (clean-room parsing, no Revit dependency) is categorically absent from 5 of 6 repos.
- The sixth, `cad2data`, matches rvt-rs on the no-Revit-needed capability and even ships an MCP server — but its core converter is **proprietary and non-commercial-only**; an enterprise AEC firm doing paid client work must buy a license to use it at all. rvt-rs is Apache-2.0: free for commercial use, source-available, and embeddable directly as a Rust library/crate rather than only as a black-box executable.
- On the MCP/agent-native axis, nothing comes close to ifc-lite's 125+ tools. cad2data's single MCP wrapper exposes "convert a file, query the element table" — a thin CLI shim. ifc-lite is built MCP-first, for agentic workflows that need fine-grained, composable IFC operations (not just one coarse convert-and-query action).

The capability none of these six repos offer: **a fully open-source, no-Revit-required, embeddable Rust/npm toolchain with deep agent-native (MCP) tooling, usable commercially without a licensing fee.** That combination — not any single feature in isolation — is the actual competitive gap rvt-rs + ifc-lite occupies.

## 4. Market gap analysis

If rvt-rs existed as a C# port instead of a clean-room Rust reader, it would most directly compete with the Revit-add-in ecosystem (`RevitAddInManager`-adjacent tooling, the glTF exporters) — but that comparison is almost a category error, because a C# port would, like all five Revit-dependent repos above, still require a live Revit license to run. It would gain nothing over `Revit2glTF` or `cad2data` on the dimension that matters (Revit independence) while losing rvt-rs's actual differentiator.

The real missing competitor is narrower and more interesting: **there is no open-source (permissive-license), Revit-independent RVT/RFA reader other than rvt-rs.** `cad2data` is the only repo in this landscape that does the "read without Revit" trick at all, and it does so as closed, non-commercial-gated binaries. No project in this survey offers that capability under an Apache/MIT/BSD-class license. That is the gap — not a hypothetical C# port, but the absence of *any* OSS alternative to a single proprietary vendor (DataDrivenConstruction) for headless, Revit-free RVT parsing.

## 5. Procurement implications

A realistic enterprise AEC toolchain assembled from what's on the market today would likely combine:

- **`RevitBatchProcessor`** (free, GPL-3.0) for the specific job it's built for: running real Python/Dynamo scripts against live Revit across many project files — model health checks, project audits, bulk upgrades. This requires Revit seats regardless of what else is adopted.
- **`RevitAddInManager`** (free, MIT) as a developer productivity tool during in-house add-in development — it's not a procurement decision so much as a dev-tools default.
- Either **Autodesk's native IFC exporter** (bundled with Revit) or a **paid `cad2data` commercial license** for RVT→IFC/Excel/GLB conversion pipelines, especially where batch/CI automation or cross-platform (Linux/macOS) conversion is needed outside a Revit-licensed Windows box.

Where rvt-rs + ifc-lite slots in: **primarily as a replacement for the `cad2data` commercial license in CI/cloud/serverless conversion and extraction pipelines**, not as a replacement for RevitBatchProcessor or the add-in tools (those operate in a different layer — live Revit sessions and in-app developer tooling that rvt-rs/ifc-lite don't attempt to touch). Specifically:

- **Replaces** `cad2data`'s commercial tier wherever a firm needs headless, no-Revit RVT/IFC parsing in CI, containers, or Linux/macOS infrastructure, and wants to avoid both the per-use non-commercial EULA restriction and the ongoing licensing cost of a proprietary binary vendor.
- **Complements** `RevitBatchProcessor`: use RBP where you genuinely need to drive a live Revit session (model edits, Dynamo scripts, dialog handling); use rvt-rs for pure read-only metadata/geometry extraction at any scale, on any OS, with zero Revit seats consumed.
- **Fills a genuine, previously vendor-locked gap** for AI-agent-driven BIM workflows: ifc-lite's 125+ MCP tools is an order of magnitude beyond anything else surveyed (cad2data's single wrapper tool is the next closest, and it's gated behind the same commercial licensing question). For any firm building LLM-agent pipelines over BIM data, rvt-rs + ifc-lite is the only permissively-licensed, source-available option that doesn't require either a Revit install or a paid non-commercial-use exception.
